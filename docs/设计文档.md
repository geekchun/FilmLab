# FilmLab 设计文档

| 项 | 内容 |
|---|---|
| 软件名称 | **FilmLab** |
| 图标 | 胶卷图标（35mm 片盒 + 带齿孔片条，琥珀色 `#e6a33c` on 近黑底） |
| 定位 | C-41 彩色负片去色罩 + 虚拟印相的跨平台工具（桌面 / Android / CLI） |

## 1. 身份与品牌资源

软件名统一为 **FilmLab**（窗口标题、页面标题、Android `android:label`、APK 名、exe 资源 `ProductName`）。

| 资源 | 路径 | 用途 |
|---|---|---|
| `icon.png` 512×512 | `crates/filmlab/assets/icon.png` | 窗口/任务栏图标（`include_bytes!` 后经 `tao::window::Icon::from_rgba` 设置） |
| `icon.ico` 256×256 | `crates/filmlab/assets/icon.ico` | exe 文件图标（`build.rs` 用 `winresource` 写入 Windows 资源段） |
| mipmap 各档 | `android/app/src/main/res/mipmap-*/ic_launcher.png`（48/72/96/144/192） | 安卓启动图标 |
| adaptive 前景 | `android/app/src/main/res/drawable/ic_launcher_foreground.png`（432） | Android 8+ 自适应图标前景，背景色 `#101218`（`values/colors.xml`） |

改图标只需替换 `icon.png` 与 `icon.ico`，再按 §7.4 重新导出安卓各档；`build.rs` 里的 `rerun-if-changed` 保证 exe 资源随图标更新重新链接。

## 2. 目录结构

```
Cargo.toml                 工作区（4 个成员）
crates/
  film-core/               算法内核（无 UI、无 IO 依赖）
    src/image.rs           浮点图、编解码、线性化
    src/model.rs           负片模型、串扰矩阵、卷档案
    src/neg.rs             密度域反演（片基检测 / 解析解）
    src/print.rs           虚拟印相（相纸曲线、自动色调、风格）
    src/pipeline.rs        端到端编排（含片框遮罩）
    src/calib.rs           片基/增益/d_ref 估计、遮罩判据
    src/synth.rs           合成负片（自检用）
    src/metrics.rs         PSNR/ΔE/中性漂移等检验指标
  filmlab/                 桌面端（tao + wry + 内嵌 ui.html）
    src/main.rs            事件循环、窗口、CLI 探针参数
    src/session.rs         UI 会话：命令分发、缓存、校准、导出
    assets/ui.html         前端（单文件，无构建步骤）
    assets/icon.*          图标资源
    build.rs               Windows 资源（图标 + 版本信息）
  film-cli/                命令行（子命令 synth / invert / analyze / selftest）
  film-android/            安卓 cdylib（JNI 桥，复用 film-core）
android/                   手写 APK 构建（aapt2 + d8 + apksigner，无 Gradle）
docs/                      调研文档与本设计文档
```

## 3. 架构与数据流

```
ui.html（滑杆/裁剪/导出）
   │  JSON IPC: {id, cmd, ...}
   ▼
session.rs  ──缓存命中──► 只重渲染
   │  未命中
   ▼
film-core::pipeline
   ├─ neg::Samples::analyze     测片基（边缘带橙色块中位段）+ 最密处
   ├─ neg::Negative::solve      D = log10(base/x) → 解析式印相参数
   ├─ print 曲线                P = exposure*(1+black-10^E) → γ → 高光柔化 → sRGB
   └─ 片框遮罩                  三通道同时 > base*k 判纸白
   ▼
base64 JPEG/PNG 回传 → 前端替换画布
```

**缓存策略**：换图或换片基才重算校准（片基、增益、`anchor_t`、自动色调端点）；拖动曝光/反差/CMY/风格/片边只重渲染。

**IPC 命令**：`demo`、`openPath`、`openData`、`render`、`rotate`、`crop`、`restoreCrop`、`resetGeom`、`export`、`reset`。所有响应带 `id`，异步进度用 `window.__fm` 回调。

## 4. 算法要点

1. **密度域而不是白平衡**：`D = log10(base / x)`，片基归一为 0。中性灰在三层上的 `D` 相等，所以颜色校准的自由度只有"片基测没测准"。
2. **片基检测有两套实现，判据相近但不共享**：
   - `neg::detect_base`（内核直出）：画面外沿 16px 块，取平坦块中的橙色色域块（`G/R 0.35–0.85`、`B/R 0.05–0.65`），再取中位段均值；无橙色块时退回全部平坦块的中位段。中位段而非最亮段，避免把片边漏光当 Dmin。
   - `calib::estimate_base`（会话路径）：带 `confidence` 的 log 亮度聚类版本，供 UI 层决定是否遮罩/回退。
   两条判据改色域时须同步修改。
3. **片框遮罩**：灯箱/白纸/齿孔的透过率高于未曝光片基，相对密度为负，照常印相会被钳成片基色吞黑，故判"无胶片"后直接给纸白。门槛倍率 `k` 默认 `FRAME_K = 1.10`（实测：齿孔 R 为片基 1.126 倍，漏光带 R 仅高 6.9%，10% 恰好把漏光带挡在外面）。
4. **UI「片边」滑杆**直接暴露 `k`（0.80–2.20）：调低→更多像素判纸白（片边更白、齿孔外扩），调高→齿孔可能消失。它只改遮罩范围，不参与片基/增益拟合。
5. **印相**：`E = bias - gain·D`，`gain` 三通道相同，`bias = log10(1+black)`，使片基严格纯黑；再按相纸 γ（默认 4.0）与高光柔化编码到 sRGB。端点由 `black/gain` 钉死，调反差/曝光不会把黑点抬灰。
6. **自动色调**：显示域逐通道色阶（Auto Tone 口径），单色风格共用同端点，避免三层被各自拉满导致再偏色。

## 5. 界面

单栏三段卡片：**显影**（风格、自动色调/中调、曝光、反差、片边、青品黄）、**信息**（直方图、中性样本、进度）、**显示**。顶栏含打开/保存/重置/旋转/裁剪。裁剪只作标记不裁图：区域外片基仍按同一套参数反转，由遮罩判成纸白。导出为 16-bit TIFF（正片与遮罩）。

## 6. 平台差异

| | 桌面 | 安卓 |
|---|---|---|
| 壳 | tao + wry（WebView2，Windows 10/11 自带运行时） | WebView + JNI + cdylib |
| 图像入口 | 文件对话框、拖放 | 相机拍照、相册 SAF |
| 运行时 | 单 exe，无外部运行时（WebView2 除外） | APK，`largeHeap=true` 支撑 24MP 浮点缓存 |
| 前端 | 内嵌 `ui.html`（`include_str!`） | 构建脚本复制同一份 `ui.html` 到 assets |

## 7. 编译说明

### 7.1 通用前置

- Rust stable（MSVC 工具链）：`rustup default stable-x86_64-pc-windows-msvc`
- Windows：Visual Studio Build Tools（MSVC + Windows SDK，提供 `rc.exe`，供图标资源编译）
- 首次构建需联网拉取依赖（`winresource` 等）

### 7.2 桌面版

```powershell
cd <仓库根>
cargo build --release -p filmlab      # 产物 target\release\filmlab.exe
cargo run   --release -p filmlab      # 直接运行（默认加载演示负片）
```

双击 exe 或把图片拖到 exe 上即可打开；`filmlab.exe 某负片.jpg` 也可直接开。

### 7.3 命令行版

```powershell
cargo build --release -p film-cli     # 产物 target\release\film.exe

film synth   --out neg.tif --reference ref.png       # 合成负片 + 参考正片
film invert  --input neg.tif --out pos.png --gamma 1 # 反相
film analyze --input neg.tif                        # 只做标定诊断
film selftest                                       # 合成→反演→比对指标
```

### 7.4 安卓版

前置：JDK 17、Android SDK（platform-34 / build-tools 34.0.0 / NDK 26.1）、`rustup target add aarch64-linux-android`。脚本按本机路径 `%USERPROFILE%\dev\{jdk17,sdk\}` 查找工具链，按需修改 `android/build.ps1` 顶部变量。

```powershell
powershell -ExecutionPolicy Bypass -File android\build.ps1
# 产物：android\dist\FilmLab-0.1.0.apk（首次自动生成 debug.keystore 并签名）
powershell -ExecutionPolicy Bypass -File android\build.ps1 -SkipRust   # 只改前端时复用已编译 .so
```

脚本做什么：`cargo build --target aarch64-linux-android` → 复制 `crates\filmlab\assets\ui.html` 到 APK assets → `javac` → `d8` → `aapt2`（compile/link，含 mipmap 图标）→ 装 dex 与 `.so` → `zipalign` → `apksigner`。

### 7.5 重新生成图标

以一张 1024 见方 PNG（图形居中、留白约 8%）为源，用系统 `System.Drawing` 导出各档，避免引入额外工具链：

```powershell
Add-Type -AssemblyName System.Drawing
$src = 'icon-source.png'                      # 1024×1024 源图
$crop = ...                                   # 裁成正方形内容区，去掉生成工具水印
# 512 → crates\filmlab\assets\icon.png
# 48/72/96/144/192 → android\app\src\main\res\mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}\ic_launcher.png
# 432 → android\app\src\main\res\drawable\ic_launcher_foreground.png
# 256 PNG 内嵌为 ICO 条目 → crates\filmlab\assets\icon.ico
```

ICO 采用"PNG 内嵌"格式（256×256，32bpp）：6 字节头 + 16 字节目录项 + PNG 数据，`bytesInRes`/`imageOffset=22`。

### 7.6 Windows 安装包

```powershell
powershell -ExecutionPolicy Bypass -File packaging\windows\build-installer.ps1
# 产物：dist\FilmLab-0.1.0-setup.exe（约 1.3 MB）
```

- 前置 NSIS 3（`winget install NSIS.NSIS`），脚本先查 PATH 再查常见安装位置；`-SkipBuild` 可复用已有 `filmlab.exe`。
- 打包前用 `-C target-feature=+crt-static` 重新编译：exe 不再依赖 `VCRUNTIME140(_1).dll`，未装 VC++ 运行库的机器也能直接启动（代价是首次构建需重编全部依赖）。
- 安装范围是当前用户（`%LOCALAPPDATA%\Programs\FilmLab`），不需要管理员：写入开始菜单快捷方式、可选桌面快捷方式、`uninstall.exe` 与 HKCU 卸载项。
- 静默安装 / 卸载：`FilmLab-0.1.0-setup.exe /S`、`uninstall.exe /S`。
- 运行仍需 WebView2 运行时（Win11 内置，Win10 通常随 Edge 已装）。

### 7.7 常见问题

- **`rc.exe` 找不到**：`build.rs` 只告警不失败，exe 无图标但可运行；安装 Windows SDK 后重新 `cargo build`。
- **窗口白屏**：Windows 需要 WebView2 Runtime（Win11 内置；Win10 多数已随 Edge 安装）。
- **Exif 方向**：解码时按 2.2 伽马线性化；负片翻拍建议在相机内关闭自动亮度/鲜艳模式。
- **首次运行慢**：release 使用 `lto="thin"`、`codegen-units=1`，全量首次编译约 1 分钟以上。

## 8. 测试与调试

- `cargo test --workspace`：内核单元测试（合成负片、指标、遮罩判据、打印曲线）。
- `film selftest`：端到端 PSNR/ΔE 自检。
- 桌面版内置探针（GUI 子系统同样可用，输出到 stdout）：

```powershell
filmlab.exe --neg 负片.jpg 0                 # 新内核直出：base/gain/密度分布/输出统计
filmlab.exe --neg 负片.jpg 0 --frame-k 0.95  # 调片边门槛，产物 target\neg-ours.jpg
filmlab.exe --probe 负片.jpg                 # 旧管线标定诊断
filmlab.exe --geom 负片.jpg / --basediag 负片.jpg
filmlab.exe --diff 正片.jpg 负片.jpg vivid   # 与参考正片比对
```

## 9. 已知限制

- 片基若被整幅高光带偏，颜色会整体偏亮/偏绿，需靠裁剪去掉片框或手动给 base（`--neg 图.jpg 0 0.8 0.75 0.72`）。
- 片边门槛是全局标量，无法逐区域自适应：同一张图里齿孔缺失与宽漏光带可能无法兼得。
- Android 仅 arm64-v8a；无 Gradle 工程，IDE 集成需自行补。
- 导出目前只有 16-bit TIFF（正片/遮罩），无 ICC 嵌入。
