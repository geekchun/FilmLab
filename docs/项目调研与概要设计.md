## 1. 调研：专业工具到底怎么"去色罩"

### 1.1 物理成因（决定了"不能只减一层橙色"）

C-41 彩色负片在乳剂层中加入**成色剂（彩色偶联剂）**，未反应的成色剂本身带色，形成整体橙色罩，用于补偿染料的有害吸收。关键点：**色罩不是均匀的橙色滤色片，而是随曝光密度变化**（与染料密度耦合）。因此：

- "整体白平衡 / 减一个橙色常量" → 中间调对、暗部与高光必偏；
- 正确做法是**在密度（log）域对 R/G/B 各自归一化**，把每通道片基映射到同一"零密度"，再在印相阶段重建色彩。

这是所有专业实现的共同骨架。

### 1.2 主流路线对比

| 工具 | 核心方法 | 锚点 | 优点 | 局限 |
|---|---|---|---|---|
| **Negative Lab Pro** | LR raw 管线内：转换前吸管点片基做 WB → 逐像素分通道、为每通道生成 RGB 色调曲线 → 残余蓝偏由 Temp/Tint 补偿 → Color Model/LUT 做印相风格 | 片基取样（或 Auto WB）+ 扫描仪专用 raw profile | 成品"胶味"强、调色面板成熟 | 算法不公开，本质是 look 模拟 + 曲线打点；依赖 LR；扫描仪 DNG 需专用 profile |
| **darktable negadoctor** | Cineon 密度模型：逐通道 Dmin 去罩 → `-log10` → 逐通道 slope+offset（printer lights）→ `10^u` 回线性 → 相纸 CDL 曲线 → 高光软压缩 | 逐通道 Dmin + 单标量 Dmax | **公式公开、源码级可移植**、物理正确 | 参数多，开箱效果一般，需 UI 引导 |
| **RawTherapee** | 逐通道 `T_c=(x_c/base_c)^(-1/exp)` 幂律反相 + 通道比例 + 曝光偏移 | 片基 R/G/B + 幂次 | 极简、实时 | 幂律近似而非严格 Cineon；褪色底片偏弱 |
| **NegPy（开源）** | 逐通道对数域百分位拉伸（等效去罩）→ H&D 曲线印相（toe/直线/肩部）→ ISO-R 相纸分级 → 中和轴去色偏 | 片边自动检测，不强制取片基 | 无需相机 profile 也能出片；相纸档案取自厂商数据表 | 自动测光对极端场景仍需手动兜底 |
| **NegBase / Filmeon** | 同为 Cineon 双锚点，γ≈0.6 或相纸曲线 | 自动/手动选锚 + 灰点 | 工业标准数值可作默认 | 生态小 |

**NLP 机制要点**：转换前在 **raw** 上用吸管点片基做白平衡（TIF 扫描件禁止在 LR 做 WB）；转换时引擎"分通道、算色彩校正、为图像构建色调曲线"，落地形式是 **LR 的 R/G/B 三条色调曲线打点**；色罩残留的蓝偏由 Temp/Tint 手动补偿，官方明确指出"Temp/Tint 归零几乎永远不平衡，绝大多数情况必须加暖"。→ NLP 属于**观感模拟**，不能直接移植；可借鉴的是它的面板组织（Color Model / Pre-saturation / Border Buffer / Tone Profile / WB 预设）。

### 1.3 可移植的核心公式（negadoctor 源码级，逐通道 c）

```
t      = max(linear_in[c], 2^-32)
D      = log10(t / Dmin[c])                 # 逐通道去罩，Dmin=片基
u      = (wb_high[c]/Dmax) * D + wb_high[c] * offset * wb_low[c]
T      = 10^u                               # 回到线性透射率
p      = max(0, E*(1+B-T))                  # 印相曝光 E + 相纸黑 B
q      = p^gamma                            # 相纸反差（默认 gamma=4）
out    = q                                       , q <= s
       = s + (1-e^{-(q-s)/(1-s)})*(1-s)          , q >  s   # 高光 soft clip
```

默认值（源码）：`Dmin=(1.00,0.45,0.25)`（片基归一，R 置 1）、`Dmax=2.046`、`offset=-0.05`、`B=0.0755`、`gamma=4.0`、`E=0.9245`、`s=0.75`。

自动取样器（同样来自源码，可直接复用）：

```
Dmin     = 取样区代表色（逐通道）
Dmax     = max_c log10( Dmin_c / min_c )
offset   = min_c [ log10(Dmin_c/max_c) / Dmax ]
wb_low   = vmin / [log10(Dmin_c/picked_c)/Dmax]        , vmin 为三通道最小
wb_high  = | 1 / (offset*wb_low - log10(Dmin_c/picked_c)/Dmax) |，再按最小值归一
```

**Auto Dmin（片基自动检测）可复用 NegPy 的做法**：在片框外侧 15% 区域内找"平坦小块"（8px 块，std/mean < 0.03、未削顶），按亮度以 0.04 log 间隔聚类，取"至少 5 块的最大簇"中位数；找不到（无片边/胶片充满画面）则回退到逐通道 99.9 百分位。

### 1.4 调研结论

| 结论 | 决策 |
|---|---|
| 密度域 Cineon 是行业标准，但"逐通道独立减法 + 固定印相曲线"忽略了**染料串扰**与**色罩随密度耦合**——这正是所有工具至今仍需逐帧手调的根本原因 | **不移植**；自研"密度矩阵解耦 + 卷级联合求解"（§5.6），negadoctor 仅作**对拍基准**（同参数 PSNR 校验） |
| 单标量 Dmax（而非逐通道）可避免主体色被"均衡掉"去饱和 | 采用标量 Dmax |
| 白平衡的正确位置在 log 密度的逐通道 slope/offset（printer lights） | 采用，不做线性正片增益、不经 temp/tint 黑体往返 |
| 仅"整体白平衡"不足以去罩；需通道级标定 + 中和轴去色偏 | 采用"片基 Dmin + 中和轴（cast removal）"双层校正 |
| 相纸模型（toe/直线/肩部 + ISO-R 分级）能显著提升成品观感 | V1 迭代引入 H&D 曲线 + 相纸档案 |
| 自动参数必须跨卷验证，禁止对单帧过拟合 | 强制"卷级标定 + 多卷回归测试" |
| NLP 的 look 不可复刻，但其交互组织值得借鉴 | 借鉴面板结构，不追算法等价 |

## 2. 产品定位与范围

### 2.1 定位

面向"自己扫描 135/120 彩色负片"的摄影者与小工作室：**导入 → 自动去罩 → 少量滑杆微调 → 批量导出 16-bit 正片**，无需 Lightroom、无需相机 profile、无需点片基也能出片（点片基则更准）。

### 2.2 功能范围

| 阶段 | 内容 |
|---|---|
| **MVP** | RAW/16-bit TIFF/JPEG 导入；自动片基检测去罩；negadoctor 印相曲线；曝光/反差/CMY；灰点取样；单帧导出 16-bit TIFF；sidecar 参数保存；中英界面 |
| **V1** | 卷级标定与批量；中和轴自动去色偏；相纸档案 + ISO-R 分级；曲线编辑器；ICC 输出（sRGB/AdobeRGB/ProPhoto/P3）；.cube LUT 导出；平场校正；直方图/波形/矢量示波器；GPU 加速 |
| **V2** | E-6 反转片与黑白负片；IR 除尘；颗粒/晕光；局部调整；多卷工程库；打印排版 |
| **不做** | 追平 NLP 的 look/LUT 生态；扫描仪驱动；云端协作 |

## 3. 技术选型

### 3.1 约束推导

- "单安装包 + 零外部依赖" → 排除 Electron 之外的 WebView 方案（WebView2 需随包内置 180MB 或联网安装）；排除 .NET/Python/Java 运行时；
- 图像管线要求 f32 线性光、大图（45MP+）、实时预览（<60ms/帧）；
- 需要 GPU 与 CPU 结果一致（导出质量与预览一致性）；
- 需要 16-bit TIFF、ICC、RAW 解码、批量并行。

### 3.2 候选对比

| 方案 | 安装包 | 零依赖 | 图像性能 | UI 难度 | 结论 |
|---|---|---|---|---|---|
| **Rust + egui/eframe + wgpu** | ~20MB 单 exe | ✅ 静态 CRT，无需任何运行时 | 极高（f32/SIMD/wgpu→DX12） | 中（原生控件需自绘） | **推荐** |
| Rust + Tauri 2（Web UI） | 内嵌 WebView2 fixedRuntime ≈ 180MB；或 embedBootstrapper 1.8MB 但**需联网** | ⚠️ 需打包固定版 WebView2 才算真正零依赖 | 高（预览需 WebGL2 再写一套 shader） | 低（Web 前端生态） | 备选（若更看重 UI 精致度） |
| Electron + NSIS | ~120–150MB | ✅ 自带 Chromium | 中（两套 shader 又要对齐） | 低 | 不推荐（体积/内存大） |
| .NET 8 WPF 自包含 | ~60–90MB | ✅ | 中（GPU 计算需自建 D3D 管线） | 中高 | 不推荐 |
| Qt6 静态 | ~40MB | ✅ | 高 | 中 | 不推荐（静态构建与 LGPL 合规成本高） |
| Python + PyInstaller | ~300MB+ | ⚠️ | 低 | 低 | 不推荐（启动慢、异常难排查） |

### 3.3 最终选型

**Rust 2024 + egui/eframe（UI）+ wgpu（GPU 计算/显示）+ rayon（CPU 并行）**

理由：单一语言贯穿解码、算法、UI、导出；无 GC、f32 + SIMD；wgpu 统一 DX12/Vulkan/Metal，预览与导出**共用同一份 WGSL 内核**，从根上消除"预览与导出不一致"；静态 CRT 使产物是真正的单文件，安装包只需打包资源。

**打包**：Inno Setup 6 生成单文件 `*.exe` 安装器（默认按用户安装、免 UAC），同时提供便携 zip。
**体积预算**：exe 12–18MB + 资源（ICC/相纸预设/字体/图标）≈ 20–28MB。

### 3.4 关键依赖与许可

| 用途 | 库 | 许可 |
|---|---|---|
| RAW 解码 | `libraw`（build.rs 静态编译，CDDL 分支）或纯 Rust `rawler`（LGPL） | 需在"关于"页声明；静态链接选 CDDL 条款 |
| TIFF/PNG/JPEG | `image` / `tiff` | MIT/Apache |
| JPEG XL（可选） | `jxl-oxide` / `libjxl` | MIT / BSD |
| ICC | `lcms2`（静态）或纯 Rust `moxcms` | MIT / Apache |
| GPU | `wgpu` + `naga` | MIT/Apache |
| UI | `egui` / `eframe` / `egui-plot` | MIT/Apache |
| 并行 | `rayon` | MIT/Apache |
| 序列化 | `serde` + `json` | MIT/Apache |

> 合规要点：LibRaw 采用 **CDDL（文件级弱 copyleft）** 静态链接合规性优于 LGPL；若坚持 LGPL，需随包提供可重链接的目标文件。

### 4.3 数据流

- **交互**：解码（降采样到工作分辨率，缓存）→ 参数变更 → GPU kernel（或 CPU 分块）→ 显示纹理 → 直方图/波形。
- **导出**：原分辨率 → 分块（默认 2048×2048 重叠 16px）→ GPU/CPU → 拼回 → ICC → 编码落盘。
- **批量**：多线程生产/消费者，GPU 队列串行 + CPU 并行。

## 5. 核心算法设计

### 5.1 九阶段管线

| # | 阶段 | 内容 | 域 |
|---|---|---|---|
| 0 | 解码 | RAW → 线性透射率 f32（`raw` 输出、gamma=1、unity WB）；TIF 按 gamma 1.0/1.8/2.2/sRGB 线性化 | 线性 |
| 1 | 几何 | EXIF 方向、旋转/翻转、裁切（先于标定，保证 ROI 只含画面） | 像素 |
| 2 | 平场（可选） | 每通道增益 `mean(blur)/blur`，参考帧 256px、AGC 限幅 [0.25,4] | 线性 |
| 3 | 片基标定 | 自动检测 Dmin（逐通道）；Dmax 单标量；卷级池化 | 线性 |
| 4 | 密度化 | `D_c = log10(max(t_c,ε)/Dmin_c)` | log |
| 5 | 串扰解混（核心） | `A^-1` 3×3 解耦：染料有害吸收 + 色罩耦合 `B` + CFA 串扰（§5.6.2） | log |
| 6 | 中和轴去色偏 | 由高/中/低三个波段"最低彩度像素"拟合 R、B 相对 G 的曲线（二次，偏移 ±0.2 限幅），置信度加权 | log |
| 7 | 印相 | `u = (wb_high/Dmax)·D + offset_c`；`10^u`；相纸曲线（MVP: CDL，V1: H&D softplus）；CMY printer lights；ISO-R 分级；相纸档案 | log→线性 |
| 8 | 风格 | 染料分离/饱和度（Oklab 保色相）、分区调色、颗粒/晕光（V2）、锐化（输出尺寸感知） | 线性/scene |
| 9 | 输出 | `I=10^-D` → ICC 变换（sRGB/AdobeRGB/ProPhoto/P3）→ 16-bit 编码 / `.cube` 烘焙 | 显示参考 |

**MVP 印相曲线（negadoctor 等价，便于对照开源结果）**

```
u   = (wb_high[c]/Dmax) * D_c + wb_high[c]*offset*wb_low[c]
T   = 10^u
p   = max(0, 0.9245*(1+0.0755-T))
q   = p^4
out = q                     if q <= 0.75
    = 0.75 + 0.25*(1-exp(-(q-0.75)/0.25))   otherwise
```

**V1 印相曲线（H&D，观感更好且可标定到相纸）**

```
v  = k*(x - x0),  k = 2.9*range/(ISO_R/100) clamped [2.0, 10.0]
v1 = Dmin + softplus(a_hl*(v - Dmin))/a_hl        # 肩部 → 相纸白
D  = Dmax - softplus(a_sh*(Dmax - v1))/a_sh       # 趾部 → 相纸黑
```
`Dmin=0.06`、`Dmax=2.3`、`a_sh/a_hl` 由 knee 宽度换算；相纸档案（Kodak Endura / Fujifilm Crystal Archive / 数码印相）提供 `Dmax/Dmin`、knee 锐度、中调 gamma。

### 5.2 自动标定策略（成败关键）

1. **Dmin**：片框外侧 15% 区域平坦块聚类（见 §1.3）→ 逐通道中位数；失败 → 逐通道 99.9 百分位；再失败 → 用户点片基。
2. **Dmax**：单标量，取"画面内最密区"的 0.1–1 百分位，不逐通道（避免主体色被均衡去饱和）。
3. **卷级池化**：同卷各帧的 Dmin/Dmax/中和轴按 `meter_inputs_key` 分组，中位数 + MAD 剔除 >3σ 的离群帧（如强逆光、大面积单色场景）。
4. **中和轴**：拟合 R/B 相对 G 的偏移，排除"绿色→黄色"（植被）与"青→蓝"（天空）色相区间，置信度低则**不校正**（拒绝把蓝主体压灰）。
5. **兜底**：任何自动步骤都必须有手动入口（点片基 / 点灰 / 手动 Dmin·Dmax / 关闭中性校正），并在 UI 显示"置信度"。
6. **削顶检测**：逐通道统计 ≥0.99 的像素比例，超过阈值即提示"扫描过曝，片基信息已丢失"。

### 5.3 卷级一致性

- 一个胶卷 = 一组参数基线（Dmin/Dmax/中和轴/相纸/分级），单帧只允许相对偏移；
- 修改后自动"应用整卷"，避免逐帧调参；
- 提供"锁定/解锁单帧"开关。

### 5.4 CPU/GPU 一致性

- **唯一真源**：`engine` 的 f32 标量实现（CPU）；WGSL 内核逐行镜像；
- 一致性测试：同一参数下 CPU 与 GPU 输出逐像素差 ≤ 1/65535（f32 运算顺序差异用 `fma` 禁用与固定循环顺序规避）；
- 导出必须走与预览**相同**的 kernel + 相同分块边界（预览就是把导出 kernel 跑在降采样图上）；
- 无 GPU / 驱动异常 → 自动回退 CPU，UI 提示，参数不变。

### 5.5 参数模型（sidecar JSON）

### 5.6 自研算法路线：物理反演 + 卷级联合求解

> 本节为技术差异化设计，**不移植任何现有工具的算法**；negadoctor 只作数值对拍基准。

#### 5.6.1 现有路线漏掉了什么

逐通道"减片基 + 打点曲线"忽略了三个物理项：

1. **染料有害吸收（串扰）**：R 通道读到的密度里含 C/M 染料成分，三通道并不独立；
2. **色罩随密度耦合**：色罩来自**未反应的成色剂**，随染料形成而减少，不是常量 `Dmin`；
3. **扫描侧二次混叠**：光源光谱 × CFA 灵敏度把上述混叠再乘一个矩阵。

→ 三个独立减法 + 逐通道曲线，本质是**三参数粗近似**，这就是专业工具仍要逐帧吸管微调的原因。

#### 5.6.2 测量模型：一个可解的线性反问题

```
d       = (d_C, d_M, d_Y)          三层染料密度（待求）
D_meas  = A · d + b0               A = M ± B （3×3）
d       = A^-1 (D_meas - b0)
```

- `M`：染料光谱在扫描通道上的投影（有害吸收）；
- `B`：成色剂色罩随染料形成的耦合斜率（负号表示色罩随密度下降）；
- `b0`：未曝光的片基色罩密度向量（唯一真正"橙色"的量，且**只有它**是常量）；
- `A`、`b0` 均可由**整卷**估计，单像素只剩一次 3×3 求解（GPU 9 次乘加，可忽略）。

**可辨识性（关键洞察，已经 M0 实测修正）**：色罩方向近似固定"橙"，与三条染料轴在密度空间**不共线**；趾部/中调/肩部三个密度段各提供一个独立约束。

> **M0 实测结论（重要修正）**：中性样本在归一后的测量密度空间是**一条过原点的直线**，因此只能定出
> `g = (g_R, g_G, g_B)` 的 **2 个相对自由度**；`A` 的 6 个非对角项**不可由中性样本辨识**。
> 实测证据：强行让 `B` 行和为 1 联合求解时，最小二乘会收敛到"三行压成同一行"的退化解
> （整幅画面变灰、染料密度误差 0.27 密度）。故最终分工为：
> **数据估增益（可见色偏的主因），先验/色卡定串扰（不可见的部分）**。
> 这也解释了为什么 negadoctor/NLP 用"逐通道曲线"就够：色偏主要就是 2 自由度的增益误差。

#### 5.6.3 正片生成：虚拟印相 + 色度学（不再打点曲线）

```
p(λ)  = d_ref - d                      # 相纸侧互补染料（d_ref = 相纸满密度锚点）
R_p(λ)= 10^-(Σ_j A'_j · p_j)           # 相纸染料光谱反射率
XYZ   = ∫ R_p(λ)·I(λ)·x̄(λ) dλ          # 给定观察光源下的三刺激值
```

- 印相曝光、CMY printer lights、相纸/ISO-R 分级成为**真实物理量**（在相纸 log-exposure 上加偏置），不是手感参数；
- 色调映射放到 **CAM16 / Oklab**（保色相、保明度），取代"逐通道曲线"，从根上避免串色与色相漂移；
- 副产品：同一模型可直接烘焙 `.cube` LUT 供 LR/PS 复用。

#### 5.6.4 卷级联合求解（取代逐帧猜测）

```
θ = { b0, A, d_ref, 曝光锚, 中和锚 }
min_θ  Σ_frames [ λ1·中性约束 + λ2·记忆色色相守恒 + λ3·覆盖/熵约束 + λ4·datasheet 先验 ]
```

- 中性约束：各密度段"最低彩度像素"在输出 Lab 的 (a,b) ≈ 0，按置信度加权；
- 记忆色守恒：天空/植被/肤色色相相对参考偏移最小化（解决"蓝天被压灰"）；
- 覆盖/熵约束：抑制整体压暗、发灰（输出直方图两端裁剪率惩罚 + 熵项）；
- 离线在缩略图上用 LM/Gauss-Newton 求解（雅可比解析），**<1s/卷**；离群帧按 MAD 剔除。

#### 5.6.5 可选：残差学习（观感）

物理骨架已消除 90% 以上色罩偏差 → 只需极小网络（逐通道 1D LUT + 3×3 微调，<10k 参数）学习"观感残差"，成对数据（扫描 vs 参考）训练；泛化好、数据需求小，且可导出 LUT。**不把神经网络放在主干**，避免不可解释与不可复现。

#### 5.6.6 与现有路线对比

| 维度 | negadoctor 移植 | NLP | 本方案 |
|---|---|---|---|
| 色罩建模 | 逐通道常量 Dmin | 曲线打点（黑箱） | `b0 + B·d`（密度相关） |
| 通道串扰 | 不处理 | 不处理 | `A^-1` 解耦 |
| 标定粒度 | 单帧手动 | 单帧吸管 | **卷级联合求解** |
| 输出色彩 | 逐通道曲线 | Lab 手调 | 光谱重建 + CAM16 保色相 |
| 褪色底片 | 需另加工具 | 需另加工具 | `A` 的层增益可直接估出 |
| 可解释/可验证 | 中 | 低 | 高（可逐项对拍） |

#### 5.6.7 已实现的估计器（`film-core/src/calib.rs::fit_gains`）

1. 逐样本算相对密度 `D = log10(base/t)`，按平均密度分趾/中/肩三段；
2. **卷级锚点**：全图样本做 IRLS——先最小二乘，再按残差 `τ = 1/(1+(r/s)^4)` 迭代收紧（`s` 取残差 25% 分位的 1.5 倍，夹在 [0.01, 0.10]），把低饱和彩色内容当离群点剔除；
3. **逐段偏移**：每段单独求解，但只允许在锚点附近按"内点质量"（∈[0,1]）偏离一半——既保留"色罩随密度漂移"的自由度，又防止单段被单一大色块劫持；
4. **保守收缩**：内点质量不足 5000（等效像素）时，增益向 1 收缩（宁可不校正，也不把主体压灰）；
5. 全部线性代数统一走 `solve_linear`（带部分主元 + λ 正则）；采样上限 30 万点、4 轮 IRLS，量级为单帧几十毫秒（尚未做正式基准）。

**M0 实测（合成负片，900×600，真值矩阵与先验一致）**

| 条件 | 染料密度误差（最大/平均） | PSNR | ΔE00 | 中性轴相对漂移 |
|---|---|---|---|---|
| 无噪声 | 0.0021 / 0.0007 密度 | 71.9 dB | 0.05 | ≤0.15 Lab |
| 2% 全幅噪声 | 0.0129 / 0.0050 密度 | 55.7 dB | 0.29 | ≤0.26 Lab |

**先验失配实验**（真值矩阵行增益 1.15 / 0.90，先验不知情）：`fit_gains` 估出 `g ≈ (1.008, 0.885, 1.108)`，与解析解 `(1, 1/1.15, 1/0.90)` 基本吻合；灰阶带平均彩度从 0.343 降到 0.036（约 10%）——"2 自由度增益可辨识"成立（对应 `calib::tests::gains_correct_prior_matrix_mismatch`）。

#### 5.6.8 代价与分期

- 依赖：染料/相纸光谱曲线（厂商 datasheet + 少量实测拟合）、标准色卡做相机 CFA 自标定；
- 分期：**A** 矩阵解耦 + 单帧求解（2 周，与 negadoctor 对拍）→ **B** 卷级联合求解（3 周）→ **C** 光谱/感知输出（3 周）→ **D** 残差 LUT（可选 4 周）；
- 风险隔离：MVP 先用"`b0` + 简化 A（对角占优）"，B/C 作为 V1 升级路径，保证早期可交付。

## 6. UI / UX 设计

```
┌──────────────────────────────────────────────────────────────┐
│ 工具栏：导入 │ 胶卷 ▾ │ 自动标定 │ 复制参数 │ 导出 │ 设置     │
├──────────┬───────────────────────────────┬───────────────────┤
│ 胶卷列   │           画布                │  右侧参数面板     │
│ 帧缩略图 │  原图/正片切换(W) · 缩放 · ROI │ ① 底片 ② 印相     │
│ 分组/星标│  叠加：直方图/波形/矢量/削顶告警│ ③ 色彩 ④ 输出     │
├──────────┴───────────────────────────────┴───────────────────┤
│ 状态栏：分辨率 · 色彩空间 · 渲染耗时 · GPU/CPU · 卷参数是否一致 │
└──────────────────────────────────────────────────────────────┘
```

- **右侧面板顺序固定**（与算法数据流一致，避免"在错误的动态范围上调参数"）：
  ① 底片（片基/Dmin、Dmax、平场、黑白/彩色）→ ② 印相（曝光、相纸、分级、CMY、纸黑/纸白）→ ③ 色彩（自动去偏强度、WB、分区、染料分离、曲线）→ ④ 输出。
- **交互要点**：空格拖动平移、滚轮缩放、`Alt` 叠加削顶警告、`\` 按住看负片、右键取色/取点、参数双击复位、`Ctrl+C/V` 复制到整卷。
- **反馈**：每个自动参数旁显示置信度条；失败时给"一键手动"入口；渲染 >80ms 时显示降级预览（1/4 分辨率）。
- **国际化**：中文/英文，内置 Noto Sans SC 子集。
- **可访问性**：键盘全流程、色盲友好的示波器配色。

## 9. 打包与分发（单安装包）

- **构建**：`cargo build --release --target x86_64-pc-windows-msvc`，`RUSTFLAGS="-C target-feature=+crt-static"` → 无 VC++ 运行库依赖。
- **安装器**：Inno Setup 6，单个 `FilmMask-Setup-x.y.z.exe`：
  - 默认 per-user 安装（`{localappdata}\Programs\FilmMask`），免管理员；
  - 资源内联（ICC、相纸档案、字体、LUT 模板）；
  - 卸载保留用户 sidecar/缓存（可选清理）；
  - 同时输出便携版 zip（解压即用）。
- **体积预算**：exe 12–18MB + 资源 5–8MB → 安装包 20–28MB。
- **签名**：OV/EV 代码签名证书（避免 SmartScreen 拦截）；安装器与主 exe 均签名。
- **更新**：V1 内置"检查更新"（下载签名后的新安装器，校验 sha256 + 签名后静默升级）；MVP 只放官网版本号提示。
- **零依赖验证清单**（CI 中自动执行）：干净 Win10 1809 / Win11 虚拟机安装 → 启动 → 解码 → 导出；确认未触发任何运行库安装、未访问网络。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 无片边/片基被裁掉，自动 Dmin 失败 | 整体偏色 | 百分位兜底 + 手动点片基 + 置信度提示 |
| 大面积单色主体（蓝天、草地、红墙）被"均衡"压灰 | 成品发灰 | 单标量 Dmax + 中和轴色相排除 + 置信度阈值（宁可不校正） |
| 老片褪色/偏色（染料失衡） | 无法用统一参数 | V1 增加 fade restoration（对角存活率矩阵）与分波段校正 |
| 扫描削顶/黑电平偏移 | 高光或暗部信息丢失 | 削顶告警 + 黑电平扣除 + 平场校正 |
| 不同扫描仪/相机色彩偏移 | 同卷不同源不一致 | 卷级池化 + 可选"扫描仪档案"（3×3 串扰矩阵标定） |
| CPU/GPU 结果不一致 | 预览与导出差异 | 单一 WGSL 内核 + 一致性回归（≤1/65535） |
| 自动参数对单帧过拟合 | 整卷发暗/发暖 | 强制多卷回归测试集（≥4 卷 × 3 场景） |
| 静态链接 LibRaw 许可 | 合规风险 | 选 CDDL 条款 + 关于页声明 + 源码可获取说明 |
| GPU 不可用（老显卡/远程桌面） | 无法预览 | CPU 回退，自动降级并提示 |
